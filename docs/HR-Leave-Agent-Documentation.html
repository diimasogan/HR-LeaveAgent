Executive summary

The HR Leave Assistant is an AI agent for PT Nusantara Digital Solutions (a fictitious company) that lets employees check leave balances and policies, track the status of their requests and submit new leave for manager approval — in English or Bahasa Indonesia.

The agent runs in Boomi Agentstudio. Its five tools are Boomi Web Services processes that enforce identity, authorisation and the leave policy on the server, so a prompt can never talk the agent into showing someone else’s data or bypassing a rule.

Background

Leave questions are frequent, repetitive and time-sensitive. Answering them by hand costs HR time, while self-service portals are often hard to navigate.

Slow answers

Employees wait for HR to answer simple balance and policy questions.

Rejected requests

Requests fail late because of notice periods, balances or maximum days that the employee did not know about.

Privacy risk

A chatbot with broad data access could leak colleagues’ leave or health information.

Business value

Instant self-service

Answers in seconds, any time, in the employee’s language.

Right first time

The agent checks balance and policy before submitting and suggests compliant alternatives.

HR focuses on people

Sensitive cases (harassment, injury, long sick leave) are escalated to a person.

Secure by design

Identity and permissions are enforced by Boomi, independent of the LLM.

Full audit trail

Every tool call is logged with requester, employee, result and access basis.

Reusable pattern

API process → authorise sub-process → logic sub-process works for any HR or ERP tool.

Solution architecture

Layered process design

  • API process (“HR Agent Tool API – …”): Web Services Server listener. Reads query parameters or the JSON body, calls the sub-processes and returns the JSON response.
  • [SUB] HR Authorize Requester: one shared authorisation step for all tools. Returns the access basis or a deny code.
  • [SUB] HR Tool – …: business logic per tool, reading the Cross Reference Tables. Submit runs a Business Rules step with the 9 policy rules.
  • [TEST] HR Leave Agent Tools Harness: runs every tool with the demo personas to regression-test the rules.

The 9 rules checked on every submission

  1. Leave type is recognised.
  2. Employee is active.
  3. Working days > 0.
  4. End date is not before start date.
  5. Backdating window (Sick 7 days, Special 3 days).
  6. Notice period (Annual 7 days, Parental 30 days).
  7. No more than 12 months ahead.
  8. Maximum consecutive working days per type.
  9. Sufficient balance.

Setup & operations

  1. Deploy the 5 “HR Agent Tool API” processes to an Atom Cloud environment with the shared web server enabled.
  2. Import agent/hr-leave-tools.openapi.yaml as API tools in Agentstudio (Basic auth with the Atom Cloud user), or run python3 -I agent/agentgarden_build.py <project> [--deploy].
  3. Paste the instructions from agent/hr-leave-agent-instructions.md and enable the platform guardrails.
  4. To change mock data, edit the four Cross Reference Tables and redeploy the 5 API processes — deployed packages keep the table version they were deployed with.
  5. Credentials stay in a local .env and are never committed.

Limitations & next steps

Demo storage

New requests are acknowledged but not stored, so a status lookup of LR-YYYY-9NNN returns REQUEST_NOT_FOUND.

Connect a real HRIS

Swap the Cross Reference Tables for an HRIS connector (e.g. Workday, SAP SuccessFactors) without changing the agent.

Single sign-on

Take requesterId from the SSO identity instead of the conversation.

Manager actions

Add approve/reject tools for managers with their own approval step.

Public holidays

Read the official holiday calendar instead of assuming it.

Notifications

Notify the approver by e-mail or chat when a request is created.
