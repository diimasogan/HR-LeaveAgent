Ringkasan eksekutif

HR Leave Assistant adalah AI agent untuk PT Nusantara Digital Solutions (perusahaan fiktif) yang membantu karyawan mengecek saldo dan kebijakan cuti, melacak status pengajuan, dan mengajukan cuti baru untuk disetujui atasan — dalam Bahasa Inggris atau Bahasa Indonesia.

Agent berjalan di Boomi Agentstudio. Kelima tool-nya adalah proses Boomi Web Services yang menerapkan identitas, otorisasi, dan kebijakan cuti di server, sehingga prompt apa pun tidak bisa membuat agent menampilkan data orang lain atau melewati aturan.

Latar belakang

Pertanyaan soal cuti sering muncul, berulang, dan butuh jawaban cepat. Menjawabnya secara manual menyita waktu HR, sementara portal self-service sering sulit digunakan.

Jawaban lambat

Karyawan menunggu HR untuk pertanyaan sederhana soal saldo dan kebijakan.

Pengajuan ditolak

Pengajuan gagal di akhir karena masa pemberitahuan, saldo, atau batas hari yang tidak diketahui karyawan.

Risiko privasi

Chatbot dengan akses data yang luas bisa membocorkan data cuti atau kesehatan rekan kerja.

Nilai bisnis

Layanan mandiri instan

Jawaban dalam hitungan detik, kapan saja, dalam bahasa karyawan.

Benar sejak awal

Agent mengecek saldo dan kebijakan sebelum mengajukan dan menyarankan alternatif yang sesuai.

HR fokus pada manusia

Kasus sensitif (pelecehan, cedera, sakit panjang) diteruskan ke manusia.

Aman sejak desain

Identitas dan izin diterapkan oleh Boomi, tidak bergantung pada LLM.

Jejak audit lengkap

Setiap pemanggilan tool dicatat beserta peminta, karyawan, hasil, dan dasar akses.

Pola yang dapat dipakai ulang

Pola proses API → sub-proses otorisasi → sub-proses logika bisa dipakai untuk tool HR atau ERP apa pun.

Contoh penggunaan

1. Cek saldo saya

Tool: get_leave_balances

SebelumKirim e-mail ke HR dan menunggu balasan.
Dengan asisten“Berapa sisa cuti tahunan saya?” → tersedia 9 hari, termasuk hari yang masih pending.

2. Ajukan cuti

Tool: get_leave_balances, get_leave_policies, submit_leave_request (perlu persetujuan)

SebelumIsi formulir, lalu ditolak beberapa hari kemudian karena aturan yang tidak diketahui.
Dengan asistenAgent menghitung hari kerja, menampilkan ringkasan, mengajukan hanya setelah “ya”, dan menjelaskan aturan yang gagal beserta alternatif tanggal.

3. Lacak pengajuan

Tool: get_leave_request_status

SebelumBertanya ke atasan atau HR soal posisi pengajuan.
Dengan asistenStatus, penyetuju, dan komentar penyetuju dalam bahasa sederhana.

4. Tampilan atasan

Dasar akses: MANAGER (hanya baca)

SebelumAtasan meminta data saldo tim ke HR.
Dengan asistenAtasan dapat melihat saldo bawahan langsung tetapi tidak bisa mengajukan atas nama mereka.

Arsitektur solusi

Desain proses berlapis

  • Proses API (“HR Agent Tool API – …”): listener Web Services Server. Membaca parameter query atau body JSON, memanggil sub-proses, lalu mengembalikan respons JSON.
  • [SUB] HR Authorize Requester: satu langkah otorisasi bersama untuk semua tool. Mengembalikan dasar akses atau kode penolakan.
  • [SUB] HR Tool – …: logika bisnis per tool yang membaca Cross Reference Tables. Submit menjalankan langkah Business Rules dengan 9 aturan kebijakan.
  • [TEST] HR Leave Agent Tools Harness: menjalankan semua tool dengan persona demo untuk uji regresi aturan.

9 aturan yang dicek setiap pengajuan

  1. Jenis cuti dikenali.
  2. Karyawan aktif.
  3. Hari kerja > 0.
  4. Tanggal selesai tidak sebelum tanggal mulai.
  5. Batas mundur tanggal (Sakit 7 hari, Alasan penting 3 hari).
  6. Masa pemberitahuan (Tahunan 7 hari, Melahirkan 30 hari).
  7. Tidak lebih dari 12 bulan ke depan.
  8. Batas maksimum hari kerja berturut-turut per jenis.
  9. Saldo mencukupi.

Penyiapan & operasional

  1. Deploy 5 proses “HR Agent Tool API” ke environment Atom Cloud dengan shared web server aktif.
  2. Impor agent/hr-leave-tools.openapi.yaml sebagai API tool di Agentstudio (Basic auth dengan user Atom Cloud), atau jalankan python3 -I agent/agentgarden_build.py <project> [--deploy].
  3. Tempel instruksi dari agent/hr-leave-agent-instructions.md dan aktifkan guardrail platform.
  4. Untuk mengubah data mock, edit keempat Cross Reference Table lalu deploy ulang 5 proses API — paket yang sudah di-deploy memakai versi tabel saat deploy.
  5. Kredensial disimpan di .env lokal dan tidak pernah di-commit.

Keterbatasan & langkah berikutnya

Penyimpanan demo

Pengajuan baru hanya dikonfirmasi tanpa disimpan, sehingga pencarian status LR-YYYY-9NNN menghasilkan REQUEST_NOT_FOUND.

Hubungkan HRIS sungguhan

Ganti Cross Reference Table dengan konektor HRIS (mis. Workday, SAP SuccessFactors) tanpa mengubah agent.

Single sign-on

Ambil requesterId dari identitas SSO, bukan dari percakapan.

Aksi atasan

Tambahkan tool setujui/tolak untuk atasan dengan langkah persetujuan tersendiri.

Hari libur nasional

Baca kalender libur resmi alih-alih mengasumsikannya.

Notifikasi

Beri tahu penyetuju lewat e-mail atau chat saat pengajuan dibuat.
